# Deyan Peshev — AI Infrastructure & Cloud-Native Engineer

Portfolio site: Next.js 15, React 19, TypeScript, Lucide icons, no UI framework. Both routes prerender to
static HTML, so the published pages contain the real numbers rather than a client-side fetch.

## Pages

| Route | Contents |
|---|---|
| `/` | Profile, six engineering projects, experience, skills, credentials, contact |
| `/benchmarks` | Project 01's evidence: weighted leaderboard (47 models), serve-runtime throughput read from the exported PDF tables, the Blackwell build constraint, and the 34-model strict screen |

## Where the numbers come from

Nothing on `/benchmarks` is typed by hand. The page renders `data/benchmarks.json`, which is generated by the
evaluation harness repository (`data/build_dataset.py` reading the recorded run artifacts) and copied here by:

```bash
npm run sync-data     # node scripts/sync-data.mjs
```

The sync step also writes `data/provenance.json` (model count, run count, assertion totals) and strips
`meta.source_root`, because the harness dataset records the machine it was built on and a public site should
not carry that path. If this site and the harness ever disagree, the harness is the source of truth and this
repository is stale — re-run the sync instead of editing a number.

Claims the audit removed are not repeated here. The earlier figures on this page ("27 models evaluated",
"11 production candidates identified", "13 evaluation categories", and the 94 tok/s vs 0.4 tok/s comparison)
came from CV wording that the raw artifacts did not support; they are replaced by artifact-derived ones
(65 models with a recorded result, 7,708 scored assertions across 13 runs, 12 weighted categories). The
"production candidates" count survives nowhere, because no automatic cutoff exists in the harness.

## Run / build

```bash
npm install
npm run dev                                  # http://localhost:3000
npm run build && npx next start -p 3100
```

## Deploy to Vercel

1. Create a GitHub repository (suggested: `deyan-peshev-portfolio`) and push this folder to its root.
2. In Vercel: **Add New → Project**, import the repository; Next.js is detected automatically.
3. No environment variables are needed — the site is fully static.
4. Replace the `metadataBase` URL in `app/layout.tsx` with the assigned `*.vercel.app` URL.

## Open before this goes public

- `public/Deyan_Peshev_CV.pdf` is served at a guessable URL and linked from the nav. A CV carries a phone
  number and an address: decide deliberately whether it is published, and consider a request-based handoff
  instead of a direct file.
- Project cards 02–06 link to the GitHub profile, not to repositories, because those repositories are not
  published yet. Replace `linkLabel: "Repository link pending publication"` in `app/page.tsx` as each one goes
  up — a portfolio link that leads nowhere is worse than an honest "pending".
- Review the final wording, dates, phone and email before publishing.
